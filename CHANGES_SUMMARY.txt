CHANGES SUMMARY
===============

Scope: deployment setup for pulseleef.com using host-installed Nginx and MySQL.
This file is the requested inventory of the changed project files.

DEPLOYMENT AND CONFIGURATION
---------------------------
.env
  Host MySQL connection settings and application secrets for this deployment.

.env.example
  Template for MySQL host, port, database, user, password, SSL mode, JWT key,
  ASP.NET environment, and domain settings.

.gitignore
  Environment-file ignore rules were removed. Review this carefully because
  .env contains credentials and secrets.

docker-compose.yml
  Builds the frontend and backend only. Removed the database container and
  Nginx container. Backend connects to host MySQL via host.docker.internal;
  frontend/backend are published on ports 3000/5000. Uploads and Data
  Protection keys use persistent Docker volumes.

EC2_DEPLOYMENT.md
  Updated server deployment instructions for host-installed MySQL and Nginx,
  DNS records, MySQL network access, Compose startup, and HTTPS setup.

Backend/Dockerfile
  Added multi-stage .NET 8 backend container build.

Backend/.dockerignore
  Excludes build outputs, Git metadata, and environment files from the backend
  Docker build context.

front end/Dockerfile
  Added multi-stage frontend build and production static serving on port 3000.

front end/.dockerignore
  Excludes node_modules, build output, Git metadata, and env files from the
  frontend Docker build context.

front end/nginx.conf
  Configures the frontend container's internal web server and API, image, and
  upload proxy routes.

nginx/pulseleef.com.conf
  Host Nginx site config for pulseleef.com. Proxies API/assets to port 5000
  and frontend requests to port 3000. HTTP is configured; HTTPS needs a host
  certificate.

FRONTEND
--------
front end/src/config/api.jsx
  Uses same-origin relative API and asset URLs by default instead of the old
  ngrok endpoint.

DATABASE MIGRATION NOTE
-----------------------
The existing EF migration files were authored for SQL Server and are not run
against MySQL. This configuration expects the MySQL schema to have already
been migrated. Future schema changes need MySQL-compatible migrations/scripts.
